# JET MEDIA — лендинг

Статический сайт без сборки и зависимостей: чистые HTML, CSS и JavaScript. Заявки уходят в Google Sheets и Telegram через Apps Script.

## Файлы

| Файл | Назначение |
|---|---|
| `index.html` | Разметка сайта, SEO- и OpenGraph-теги, JSON-LD |
| `styles.css` | Палитра и типографика брендбука, компоненты, адаптив |
| `config.js` | **CONFIG со всеми цифрами** и формулы стоимости — общие для сайта и прайса |

| `price.css` | Оформление прайс-листа: экран, печать, PDF |
| `price.js` | Тексты прайс-листа (RU/EN/TH) и подстановка цен из CONFIG |
| `price-ru.pdf`, `price-en.pdf`, `price-th.pdf` | Готовые PDF прайс-листа для отправки клиентам |

## CONFIG — единственное место, где меняются цифры

Открываете `config.js`, самый верх файла:

```js
const CONFIG = {
  appsScriptUrl: "https://script.google.com/macros/s/AKfycb.../exec",

  staffRelief: 20,                        // снижение нагрузки на персонал, %
  launchDays: "1–3",                      // срок запуска

  // THB в месяц с НДС, тариф Standard; months — длина сезона для расчёта за год
  pricing: {
    low:  { software: 1200, device: 240, months: 7 },   // апрель–октябрь
    high: { software: 3900, device: 590, months: 5 }    // ноябрь–март
  },
  premiumMultiplier: 2,                   // Premium = Standard × 2

  setupFee: 5000,                         // подключение базового пакета, THB, при подписании договора

  addons: [                               // дополнительные модули, см. «Базовый пакет и модули»
    { id: "ordering", setup: 5000, monthly: 1000,
      name: { ru: "Заказ со стола", en: "…", th: "…" },
      desc: { ru: "Гость сам делает заказ и дозаказ…", en: "…", th: "…" } },
    // …ещё пять модулей
  ],

  contract: { minMonths: 12, cancelMonths: 2 },  // срок договора и период отказа
  vat: 7,                                 // НДС, %, уже включён в цены

  priceList: {                            // только для прайс-листа
    date: "2026-10-01",                   // с какой даты действуют цены
    examples: [5, 10, 20],                // столики в таблице «Примеры расчёта»
    site: "jetmedia.dev",
    contacts: { phone: "", line: "", whatsapp: "", telegram: "", email: "" }
  },

  usdToThb: 35,                           // курс бата к доллару
  currency: "฿",

  sliders: {                              // границы и значения по умолчанию
    tables: { min: 1,   max: 50,    step: 1,  value: 10   },
    guests: { min: 200, max: 15000, step: 50, value: 1800 },
    check:  { min: 100, max: 5000,  step: 10, value: 850  },
    uplift: { min: 6,   max: 15,    step: 1,  value: 6    }   // прирост выручки, %
  },

  defaultPeriod: "month",                 // "month" или "year"
  defaultSeason: "low",                   // "low" или "high"
  debug: false
};
```

Проценты пишутся обычными числами: `6` — это 6%, а не `0.06`. Цены — в батах.

`config.js` подключают обе страницы — сайт и прайс-лист, поэтому цена, поменянная здесь, меняется везде сразу. Исключение — готовые PDF: это файлы, их нужно пересобрать (см. «Прайс-лист»).

### Как считается стоимость

Цена состоит из двух частей, и на сайте, и в прайсе они показываются раздельно:

```
Софт и поддержка  = software × множитель тарифа          // за ресторан, от числа столиков не зависит
Аренда устройств  = столики × device × множитель тарифа  // платится каждое устройство, с первого
Итого             = софт и поддержка + аренда устройств

За год            = 7 × итого низкого сезона + 5 × итого высокого   // months из pricing

множитель тарифа: Standard — 1, Premium — premiumMultiplier
```

«Софт и поддержка» вместе с арендой устройств — это **базовый пакет** (список — в разделе «Базовый пакет и модули»); под ценой в карточках тарифов так и написано: «за ресторан — базовый пакет». Всё остальное — дополнительные модули за отдельную плату. Все цены — с НДС 7%.

Бесплатных устройств, бесплатных месяцев и бесплатного подключения в расчёте нет. Подарки сомневающимся клиентам — инструмент продаж: менеджер даёт их на переговорах, на сайте и в прайсе их нет. Premium дороже ровно вдвое в обеих частях сразу — отдельные премиум-цены задавать не нужно.

**Тарифы отличаются только расходами** — рекламой сети JET MEDIA на экране или её отсутствием. Прирост выручки у них одинаковый: он зависит от ресторана (настройки меню и акций, слаженности работы персонала), а не от подписки, поэтому в калькуляторе это отдельный ползунок `sliders.uplift` — от 6 до 15%, по статистике. Клиент или менеджер двигает его на переговорах.

Контрольные точки при значениях по умолчанию:

| Столиков | Период | Софт и поддержка | Аренда устройств | Итого Standard | Итого Premium |
|---|---|---|---|---|---|
| 1 | низкий сезон, мес. | 1 200 ฿ | 1 × 240 ฿ | 1 440 ฿ | 2 880 ฿ |
| 10 | низкий сезон, мес. | 1 200 ฿ | 10 × 240 ฿ | 3 600 ฿ | 7 200 ฿ |
| 10 | высокий сезон, мес. | 3 900 ฿ | 10 × 590 ฿ | 9 800 ฿ | 19 600 ฿ |
| 10 | год | 27 900 ฿ | 10 × 4 630 ฿ | 74 200 ฿ | 148 400 ฿ |

Цены устройств — как в схеме партнёра. «Софт и поддержка» — это его абонплата (1 900 / 5 800 ฿) за вычетом трёх устройств, которые у партнёра входили в неё бесплатно: 1 900 − 3 × 240 = 1 180 ≈ 1 200 ฿ и 5 800 − 3 × 590 = 4 030 ≈ 3 900 ฿. Поэтому для зала от трёх столиков итог почти совпадает со схемой партнёра — на 510 ฿ в год меньше (10 столиков: 74 200 ฿ против 74 710 ฿), но в расчёте ничего не бесплатно.

| Что меняете | Где меняется |
|---|---|
| `sliders.uplift` | ползунок «Прирост выручки» и диапазон «+6–15%» на первом экране и у калькулятора |
| `staffRelief` | первый экран и карточка в блоке «Что получает ресторан» |
| `launchDays` | первый экран |
| `pricing.*.software` | цена в карточках тарифов, строка «Софт и поддержка» в калькуляторе, прайс-лист |
| `pricing.*.device` | цена устройства в карточках, строка «Аренда устройств» в калькуляторе, прайс-лист |
| `pricing.*.months` | расчёт за год в калькуляторе и в прайсе, подпись «7 + 5 мес.» |
| `premiumMultiplier` | цена Premium везде: и софт, и устройство |
| `setupFee` | сноска под калькулятором, блок под тарифами, прайс-лист |
| `addons` | карточки модулей под тарифами, список модулей в «Что получает ресторан», таблица модулей в прайс-листе |
| `contract`, `vat` | срок договора и НДС: блок под тарифами, вопрос «Можно ли отказаться?», прайс-лист |
| `priceList.*` | только прайс-лист: дата, примеры, адрес сайта, контакты |
| `sliders` | границы, шаг и стартовые значения ползунков |

В разметке этих чисел нет: элементы помечены атрибутами `data-claim` и `data-tpl`, значения подставляют `renderClaims()` и `renderTemplates()`. Если после правки CONFIG цифры на сайте не изменились — почти наверняка `index.html` остался от старой версии; в консоли браузера в этом случае появится предупреждение.

Исключения — готовые PDF прайса и `og-image.png`: цифры там уже нарисованы, их нужно пересобирать отдельно.

## Базовый пакет и модули

**Базовый пакет** входит в ежемесячную оплату (софт и поддержка + аренда устройств):

- устройство на каждый стол с зарядкой для телефона;
- интерактивное меню с фото и описанием блюд;
- меню на нескольких языках;
- рекомендации шеф-повара, акции и сезонные новинки;
- вызов официанта и запрос счёта;
- обновления и техническая поддержка.

Список одинаковый в карточках тарифов и в блоке «Что получает ресторан» (ключи `price.s1`–`price.s6` в `script.js`) и в прайсе (`included` в `price.js`).

**Дополнительные модули** — всё остальное. Их нужно отдельно настроить и связать с системами ресторана, поэтому у каждого — разовая плата за настройку и абонплата, которая прибавляется к ежемесячной оплате. Модули подключаются к любому тарифу, сразу или позже; цены одинаковые для Standard и Premium и не зависят от сезона и числа столиков.

| Модуль | Настройка, разово | В месяц |
|---|---|---|
| Заказ со стола | 5 000 ฿ | 1 000 ฿ |
| Интеграция с кассой | 10 000 ฿ | 1 000 ฿ |
| AI-рекомендации | 5 000 ฿ | 1 500 ฿ |
| Аналитика | 3 000 ฿ | 800 ฿ |
| Программа лояльности | 3 000 ฿ | 800 ฿ |
| Сбор отзывов | 2 000 ฿ | 500 ฿ |

Ориентиры рынка: в Таиланде FoodStory даёт QR-заказ в пакете за 990–1 990 ฿ в месяц, CRM с баллами — 450–500 ฿; у iiko модули-коннекторы стоят 500–1 100 ₽ (около 210–460 ฿), у r_keeper меню с заказом дороже меню без заказа на 2 000 ₽ (около 830 ฿); в США у Toast модули стоят $30–185 в месяц (1 000–6 200 ฿), Square Loyalty — $49 (около 1 600 ฿), сервисы отзывов — $59–90 (2 000–3 000 ฿), AI-сервисы для ресторанов — от $199 (около 6 600 ฿) плюс настройка $500–2 500. Наши цены — между азиатскими и американскими.

Онлайн-оплаты через JET MEDIA пока нет — ни сбора, ни оплаты со стола. Калькулятор считает только базовый пакет, модули в расчёт не входят — это сказано в сноске под ним.

## Калькулятор

Четыре ползунка: столики, гости, средний чек и **прирост выручки** (6–15%). Прирост один на оба тарифа и показывается над карточками. Карточки Standard и Premium отличаются только расходами:

- **Чистый результат** — прирост минус расходы, крупно. Если уходит в минус, число подсвечивается красным: для маленького зала в высокий сезон это честный ответ;
- **Софт и поддержка** — за ресторан, от числа столиков не зависит;
- **Аренда устройств** — одно на столик, каждое платное; рядом подсказка вида «10 × 240 ฿»;
- **Расходы в месяц** — сумма двух строк выше; в годовом режиме подпись меняется на «Расходы за год».

Переключатель **Месяц / Год**. Месяц считается по выбранному сезону. Год — по обоим сезонам сразу: 7 месяцев по ценам низкого и 5 по ценам высокого, поэтому в режиме «Год» переключатель сезона в калькуляторе прячется, а вместо него появляется пояснение. Выручка за год — месячная × 12: ползунки описывают обычный месяц работы зала.

Переключатель **сезона** в калькуляторе и в блоке тарифов — один и тот же: нажатие в любом месте меняет и цены в тарифах, и стоимость в расчёте.

Под калькулятором — сноска: подключение при подписании договора, что дополнительные модули в расчёт не входят, НДС, ссылка на прайс-лист. В карточках тарифов строка «Для вашего зала» показывает формулу целиком — «1 200 ฿ + 10 × 240 ฿ = 3 600 ฿» — для числа столиков, выставленного в калькуляторе.

## Прайс-лист

`price.html` — прайс-лист в виде листа A4: цены по сезонам и тарифам с НДС, примеры для 5, 10 и 20 столиков (в месяц и за год), базовый пакет, дополнительные модули с ценами, подключение и условия договора, QR-код на сайт. Открывается кнопкой «Открыть прайс-лист» под тарифами.

- **Язык** — как на сайте, или явно: `price.html?lang=en`. Такую ссылку можно отправить клиенту.
- **Цены** — из `config.js`, страница всегда актуальна.
- **Тексты** («Базовый пакет», «Подключение и условия») — в словаре в начале `price.js`. Названия и описания модулей — в `CONFIG.addons`: их берут и сайт, и прайс.
- **Контакты** — `CONFIG.priceList.contacts`. Пока пустые: в подвале только адрес сайта и QR-код, а заявку клиент оставляет в форме на сайте. Заполните телефон, LINE или Telegram — и они появятся в подвале прайса.
- **Печать** — кнопка «Печать» или `Ctrl+P`: панель сверху в печать не попадает, лист ровно A4.

**PDF для отправки.** Кнопка «Скачать PDF» на сайте и в прайсе отдаёт готовый файл `price-ru.pdf`, `price-en.pdf` или `price-th.pdf` — по языку. Это файлы, поэтому **после изменения цен или текстов прайса их нужно пересобрать**, иначе в PDF останутся старые цифры:

```
npm install -g playwright && npx playwright install chromium
NODE_PATH="$(npm root -g)" node tools/price-pdf.js
```

Скрипт открывает `price.html` на каждом языке и сохраняет PDF в корень сайта. Если текст перестал помещаться на один лист, скрипт предупредит. Запас на листе — около 3 мм: новый модуль или длинное описание уже не влезут, их придётся сокращать (или убрать строку из «Примеров расчёта» — `priceList.examples`).

QR-код в подвале прайса ведёт на `https://jetmedia.dev/` и нарисован в `price.html` готовым SVG. Если адрес сайта поменяется, код нужно сгенерировать заново.

## Условия для договора

Цифры, которые должны совпадать в прайсе и в договоре с рестораном (все — в `config.js`):

| Условие | Значение | Где в CONFIG |
|---|---|---|
| Подключение базового пакета | 5 000 ฿, оплачивается при подписании договора | `setupFee` |
| Дополнительные модули | настройка — разово при подключении модуля, абонплата модуля прибавляется к ежемесячной оплате; не зависят от сезона и тарифа | `addons` |
| Срок договора | минимум 12 месяцев | `contract.minMonths` |
| Отказ от договора | возможен в первые 2 месяца; оборудование забираем в конце оплаченного периода | `contract.cancelMonths` |
| НДС | 7%, уже включён во все цены | `vat` |
| Сезоны | высокий — ноябрь–март, низкий — апрель–октябрь | `pricing.*.months` |
| Устройства | в аренде, одно на столик, гарантийная замена за счёт JET MEDIA | — |

## Публикация на GitHub Pages

1. Загрузите файлы в корень ветки `main` — вместе с `config.js`, `price.*` и PDF.
2. Settings → Pages → Source: `Deploy from a branch`, ветка `main`, папка `/ (root)`.
3. Замените `https://jetmedia.example/` в `canonical`, `og:url` и JSON-LD на реальный адрес.

GitHub Pages кеширует файлы. После заливки обновлённых `config.js` и `script.js` открывайте сайт с `Ctrl+F5` (или `Cmd+Shift+R`), иначе браузер покажет старую версию.

**Если сайт не обновился после коммита.** Проверьте Settings → Pages → Source: должно быть **Deploy from a branch**, ветка `main`, папка `/ (root)`. При источнике «GitHub Actions» сайт собирается только файлом сборки в `.github/workflows`, а его в репозитории нет — коммиты тогда вообще не публикуются. Ход сборки видно во вкладке Actions → «pages build and deployment»: обычно минута после коммита.

## Заявки: Google Sheets + Telegram

Схема: сайт → веб-приложение Apps Script → строка в таблице + сообщение в Telegram. Токен бота хранится в свойствах скрипта на стороне Google и в исходники сайта не попадает.

1. Создайте таблицу Google Sheets, например «JET MEDIA — заявки».
2. Расширения → Apps Script. Замените содержимое на `Code.gs` из этого проекта.
3. Впишите `BOT_TOKEN` и `CHAT_ID` в функцию `setup()` и запустите её один раз.
4. Запустите `testSend()` — в Telegram придёт сообщение, в таблице появится строка.
5. Развернуть → Новое развёртывание → «Веб-приложение».
   **Запуск от имени:** от моего имени. **У кого есть доступ:** у всех.
6. Скопируйте URL (заканчивается на `/exec`) в `CONFIG.appsScriptUrl`.

### Как заявка доходит до Telegram

Сайт пробует три канала по очереди и останавливается на первом сработавшем:

1. **JSONP** — ответ Apps Script загружается обычным тегом `<script>`. Такой запрос не подчиняется правилам CORS вообще, поэтому работает и в обычном браузере, и в WebView внутри Telegram, и при этом возвращает подтверждение от сервера. Основной канал.
2. **GET через fetch** — если у ответа есть заголовки CORS.
3. **POST без чтения ответа** — последняя попытка: подтверждения не будет, но заявка дойдёт.

Для первого канала `Code.gs` отвечает на параметр `callback`. Если вы обновляете `Code.gs`, обязательно разверните **новую версию** веб-приложения, иначе ответа не будет и сайт свалится на запасные каналы.

### Если форма не отправляет

Сначала выполните в консоли браузера (F12 → Console):

```js
JM.diagnose()
```

Команда печатает по шагам: правильный ли адрес, ответил ли скрипт, и что проверить дальше. Дальше — по списку, почти всегда дело в одном из пяти пунктов:

1. **Старое развёртывание.** Правки `Code.gs` не действуют, пока не нажали: Развернуть → Управление развёртываниями → карандаш → Версия **«Новая версия»** → Развернуть. Функция `testSend()` при этом работает — она запускает свежий код напрямую, минуя веб-приложение. Именно поэтому тест внутри редактора может проходить, а сайт получать ошибку.
2. **Доступ к веб-приложению.** Нужно: запуск **от моего имени**, доступ **«У всех»**. При доступе «Только я» браузер посетителя получает страницу входа Google вместо ответа.
3. **Адрес `/dev` вместо `/exec`.** Первый работает только у владельца в залогиненном браузере.
4. **Адрес не подставлен в CONFIG.** Тогда на странице появится отдельное сообщение «Форма пока не подключена к приёму заявок», а в консоли — красная строка с подсказкой.
5. **Старый `script.js` на сайте.** GitHub Pages кеширует файлы: после заливки открывайте с `Ctrl+F5`.

Проверка веб-приложения без сайта — откройте в браузере:

```
<ваш /exec>?name=Тест&phone=+66000000000&restaurant=Test
```

Должно ответить `{"ok":true}`, в таблицу упасть строка, в Telegram прийти сообщение.

Вместе с контактами уходит снимок калькулятора: столики, гости, чек, выбранный прирост (в процентах и в батах), расходы по обоим тарифам, сезон и период.

Если Apps Script не нужен, заполните `botToken` и `chatId` в CONFIG — сайт обратится к Bot API напрямую. На статическом хостинге токен при этом виден любому посетителю.

## Языки

Все тексты сайта в объекте `I18N` в `script.js` (`ru` / `en` / `th`), 125 ключей на язык. Названия и описания модулей — в `CONFIG.addons` (`config.js`), по три языка у каждого. Тексты прайс-листа — в `PRICE_I18N` в `price.js`. Чтобы добавить язык: скопируйте блок, переведите значения, добавьте кнопку в шапке и локаль в `LOCALES`.

```html
<button type="button" class="lang-btn" data-set-lang="zh">ZH</button>
```

## Фото устройства на первом экране

`device.webp` — фото устройства с прозрачным фоном: основа — снимок без выносок, кнопки «меню» и «счёт» и USB-порты перенесены со второго снимка. Выноски сделаны вёрсткой, а не нарисованы на фото, поэтому переводятся вместе с сайтом (ключи `hero.tag1`–`hero.tag5`). Подписи — только про базовый пакет: акции и рекомендации, вызов официанта, меню с фото, запрос счёта, зарядка для телефона.

Каждая выноска — это три элемента в `index.html` с одинаковыми координатами в пикселях картинки (628×940):

```html
<polyline points="70,620 -24,620"/>                   <!-- линия: от точки к подписи -->
<span class="pin" style="--x:70; --y:620">2</span>     <!-- точка на устройстве --> 
<li class="tag tag-l" style="--x:-24; --y:620">…</li>  <!-- подпись -->
```

`x < 0` — подпись левее картинки (`tag-l`), `x` больше ширины картинки — правее (`tag-r`). На телефоне линии и подписи убираются, на точках появляются номера, а подписи выстраиваются легендой под фото.
